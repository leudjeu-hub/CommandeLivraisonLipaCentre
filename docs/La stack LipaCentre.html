La stack LipaCentre

Tout ce qui fait tourner le site de commande, de l'adresse tapée dans le téléphone jusqu'à la ligne enregistrée dans la base de données. Écrit pour quelqu'un qui débute : chaque pièce est expliquée, avec ce qu'elle fait chez nous et ce qui peut casser.

En une phrase : le code vit sur GitHub, Cloudflare construit et sert le site statique à chaque modification, le site parle à une API Python hébergée sur Render, qui range les données dans PostgreSQL chez Neon. Le nom lipace.shop est loué chez IONOS. Les commandes partent ensuite par WhatsApp vers la boutique.

Changement du 9 novembre : le compte GitHub leudjeu-hub est réactivé. La mise en ligne passe de l'envoi manuel d'un zip au déploiement automatique depuis GitHub, sur un nouveau Worker « commandelivraisonlipacentre ». Le passage n'est pas terminé : voir « Ce qu'il reste à faire ».

Le trajet d'une commande

Un client de Yaoundé ouvre lipace.shop, met deux cahiers dans son panier et commande. Voici ce qui se passe, dans l'ordre.

  1. Trouver l'adresse. Le téléphone ne connaît pas « lipace.shop ». Il demande au DNS où se trouve ce nom. IONOS, chez qui le nom est loué, a confié cette réponse à Cloudflare. Cloudflare répond : « c'est chez moi ». quelques millisecondes
  2. Charger le site. Le Worker du site (commandelivraisonlipacentre, qui remplace l'ancien Worker lipace envoyé à la main) envoie des fichiers tout prêts : la page HTML, le JavaScript (React) et les images. Il ne calcule rien, il distribue des fichiers. Chaque page (catalogue.html, panier.html…) existe déjà en HTML, ce qui affiche quelque chose même avant que le JavaScript ait fini de charger. rapide, Cloudflare a des serveurs proches
  3. Demander les données. Pour afficher les prix à jour ou enregistrer la commande, le JavaScript du téléphone envoie une requête en JSON (par exemple GET /products/ ou POST /orders/submit). Dans la version publiée pendant la suspension de GitHub, elle ne va pas directement à Render, mais au relais lipace-api.leudjeu.workers.dev. Le code actuel sur GitHub (branche main) appelle Render directement, sauf si la variable PROD_API_URL est réglée dans la construction Cloudflare. Si le client est connecté, la requête porte son jeton (une sorte de badge) dans l'en-tête Authorization.
  4. Le relais transmet (provisoire). Le relais répond lui-même aux questions de sécurité du navigateur (le CORS, voir le glossaire), retire l'en-tête qui dit d'où vient la requête, puis la renvoie telle quelle à l'API sur Render. La réponse de Render revient par le même chemin.
  5. L'API travaille. FastAPI vérifie le jeton et le rôle, contrôle les données (nom, téléphone, quantités), puis lit ou écrit dans PostgreSQL chez Neon. Pour une commande, elle crée une ligne dans orders et une ligne par article dans order_items, avec le statut « nouvelle ». si Render dormait : jusqu'à ~50 s de réveil
  6. Le message part. En même temps que l'enregistrement, le téléphone ouvre WhatsApp avec un récapitulatif déjà rédigé (articles, quartier, créneau, référence). Le site n'attend pas la réponse de l'API pour ouvrir WhatsApp.
  7. La boutique traite. La boutique reçoit le message. Le personnel ouvre /gestion, retrouve la commande par sa référence et la passe en « confirmée », puis « livrée ». Ces clics refont le trajet 2 → 5.

Les points faibles

La stack est simple et gratuite, et c'est un bon choix pour une boutique de cette taille. GitHub est revenu, mais le passage vers Cloudflare n'est pas fini et les contournements de la suspension sont encore en place. Classés du plus grave au moins grave :

Grave

La page de connexion reste blanche sur lipace.shop

Le site construit charge ses fichiers JavaScript depuis https://www.lipace.shop/assets/… alors que le visiteur est sur lipace.shop, et www ne répond pas encore. Le code sur GitHub n'écrit nulle part « www » : l'adresse vient très probablement de la variable BASE_PATH réglée dans la construction Cloudflare. Il faut la mettre à / (ou la supprimer), et brancher aussi www.lipace.shop.

Grave

Sauvegarde de nuit pas encore vérifiée

La copie chiffrée de chaque nuit tourne sur GitHub Actions. Le compte est revenu, mais côté site plus aucun robot n'a tourné depuis le 7 novembre, et GitHub ne relance pas toujours seul les tâches planifiées après une suspension. Vérifier dans l'onglet Actions du dépôt backend que la sauvegarde est de nouveau passée, sinon la relancer à la main.

Moyen

Le code sur GitHub n'est pas celui de lipace.shop

La branche main date du 28 octobre : adresse officielle github.io (balises canonical, sitemap) et appel direct à Render. Les réglages faits pendant la suspension (lipace.shop, relais) n'y sont pas. Le nouveau Worker publie donc l'ancienne configuration tant que ce n'est pas corrigé dans le code.

Moyen

Trois versions du site en ligne

L'ancien Worker « lipace » tient très probablement encore lipace.shop (Cloudflare refuse d'y brancher le nouveau tant que l'ancien le garde), le nouveau Worker tourne sur workers.dev, et GitHub Pages republie toutes les 3 heures. Il faut retirer lipace.shop de l'ancien Worker, le brancher sur le nouveau, puis couper GitHub Pages et l'app Emergent.

Moyen

Le relais ajoute un maillon

Une requête passe maintenant par deux services au lieu d'un. Si le relais tombe ou dépasse la limite gratuite de Cloudflare, le site s'affiche encore mais plus rien ne s'enregistre. Il retire aussi l'en-tête d'origine : l'API ne peut plus savoir d'où vient la requête, la protection CORS ne se fait plus qu'au relais.

Moyen

Catalogue figé et tests non bloquants

Sur GitHub Pages, catalogue.json était rafraîchi toutes les 3 heures et rien n'était publié si un test échouait. Cloudflare ne reconstruit qu'à chaque push et ne lance pas les tests avant de publier : à reprendre dans la configuration de construction ou dans un robot GitHub.

Moyen

Une commande peut n'exister que dans WhatsApp

Le site ouvre WhatsApp sans attendre la réponse de l'API, pour ne pas bloquer le client. Si l'API échoue à ce moment-là, la boutique reçoit le message mais la commande n'apparaît pas dans Gestion. C'est un compromis voulu, il faut le connaître.

Faible

Tout repose sur des offres gratuites

Render gratuit (une seule instance, 750 h par mois, donc pas de seconde API pour tester), Neon gratuit, Cloudflare gratuit. Ça suffit aujourd'hui. Le jour où le trafic augmente, Render sera le premier à limiter.

Faible

Plus de site de test

Le site de test (branche develop) était prévu sur GitHub Pages et n'a jamais été mis en service. Avec Cloudflare, chaque branche peut avoir sa propre adresse de prévisualisation (*-commandelivraisonlipacentre.leudjeu.workers.dev) : c'est la voie la plus simple.

La suite

Ce qu'il reste à faire

GitHub est rétabli et le déploiement automatique vers Cloudflare existe. Pour finir le passage, dans l'ordre :

  • dans la construction Cloudflare, mettre BASE_PATH à / (fin de la page blanche) et régler PROD_API_URL ;
  • retirer lipace.shop de l'ancien Worker « lipace », le brancher avec www.lipace.shop sur le Worker « commandelivraisonlipacentre », puis supprimer l'ancien ;
  • mettre lipace.shop comme adresse officielle dans le code (vite.config.ts, index.html, README) ;
  • désactiver GitHub Pages (deploy.yml) et l'app Emergent ;
  • corriger la liste des sites autorisés sur Render, puis supprimer le relais pour revenir à un appel direct ;
  • vérifier que la sauvegarde de nuit repart, et supprimer le robot « réveil API » devenu inutile grâce à UptimeRobot.
Les mots du métier

Glossaire

Front-end
La partie qui tourne dans le navigateur du client. Ici, le site React.
Back-end
La partie qui tourne sur un serveur et que le client ne voit pas. Ici, l'API FastAPI et la base.
API
Un ensemble de « guichets » (adresses comme /orders) auxquels un programme envoie des demandes et reçoit des réponses en JSON.
JSON
Un format texte pour échanger des données : {"quantite": 2, "nom": "cahier"}.
SPA
« Single Page Application » : le site charge une fois son JavaScript, puis change de page sans tout recharger.
Site statique
Des fichiers servis tels quels, sans calcul côté serveur. Rapide et presque gratuit à héberger.
Worker
Un petit programme qui tourne sur les serveurs de Cloudflare, près de l'utilisateur. Chez nous : un qui sert le site, un qui fait relais (provisoire), et l'ancien Worker du site à supprimer.
DNS
Le système qui traduit un nom de domaine en adresse de serveur.
CORS
Une règle des navigateurs : un site ne peut appeler une API d'un autre domaine que si cette API dit « ce site-là est autorisé ». C'est cette liste qu'on n'arrive plus à modifier sur Render.
Jeton
Une longue chaîne aléatoire reçue à la connexion. Le site la joint à chaque requête pour prouver qui est connecté, sans renvoyer le mot de passe. La base n'en garde qu'une empreinte (SHA-256).
Démarrage à froid
Le temps qu'un serveur endormi met à se réveiller. Sur Render gratuit, 40 à 60 secondes.
Déploiement
Mettre une nouvelle version en ligne.
CI
« Intégration continue » : des tests lancés automatiquement à chaque modification du code.
Migration
Un script qui modifie la structure de la base (ajouter une colonne, par exemple) sans perdre les données.
